# Claude Code 2.1.280 — settings (configurações)

Resumo verificado em 2026-09-22 contra os docs oficiais; detalhes nas fontes.

- Files: ~/.claude/settings.json (User), .claude/settings.json (Shared project, read from the primary working directory, no parent fallback), .claude/settings.local.json (Project local; outside a git repo it sits next to the project file), managed-settings.json/MDM/console (Managed), plus ~/.claude.json (global config, trust state, written by Claude Code).
- Precedence high→low: Managed > CLI args/--settings > local > project > user. Env vars are not a level; ANTHROPIC_MODEL beats the model key, ANTHROPIC_DEFAULT_MODEL applies only if no file sets model.
- List keys (permissions.allow/ask/deny, hooks, env) merge across files; deny at any level wins; rules evaluate deny → ask → allow, first match wins; allow never overrides deny; ask beats allow.
- Strict JSON only (no // comments, no trailing commas) → Settings Error dialog. Invalid single entries → Settings Warning. Use "$schema": "https://json.schemastore.org/claude-code-settings.json".
- Claude Code watches settings files and hot-reloads permissions/hooks; a .claude/settings.json created mid-session is loaded immediately and fires ConfigChange. model, effortLevel, modelSettings are read only at start.
- Keys that do NOT work from .claude/settings.json: autoMode (User or managed), skipAutoPermissionPrompt, useAutoModeDuringPlan (project file can't turn it off), permissions.defaultMode "auto"/"bypassPermissions" (v2.1.257+, user file only), modelPicker, Global-config keys. Exception: remoteControlAtStartup false IS honored from a repo file.
- Trust: outside a git repo trust is keyed on the start directory (covers subdirs); key projects["/Users/marcelomaximos/Desktop/babel-os"].hasTrustDialogAccepted in ~/.claude.json; starting in ~ keeps trust session-only. Project permissions.allow and additionalDirectories wait for exact-folder trust; deny/ask apply immediately; hooks, env, autoMemoryDirectory, statusLine/fileSuggestion/subagentStatusLine work with parent-folder trust (untrusted → status line "Off entirely", silently).
- Permission modes: default (Manual, alias manual), acceptEdits, plan, auto, dontAsk, bypassPermissions. Built-in default is auto on Pro/Max/Team (needs feature-flag fetching, which DISABLE_TELEMETRY/DO_NOT_TRACK/DISABLE_GROWTHBOOK/CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC turn off; DISABLE_ERROR_REPORTING does not). VS Code extension ignores project settings for the starting mode and claudeCode.initialPermissionMode rejects auto.
- Protected paths (.git, .claude except .claude/worktrees, .vscode, .zshrc, .mcp.json, .claude.json ...): writes never auto-approved except bypassPermissions and interactive plan mode with bypass available; allow rules do not pre-approve; auto routes to classifier; dontAsk denies; prompt offers "Yes, and allow Claude to edit its own settings for this session".
- Auto mode drops broad allow rules on entry (Bash(*), PowerShell(*), wildcarded interpreters like Bash(python*)/Bash(python *), package-manager run, Agent, Monitor); narrow rules like Bash(npm test) stay. Whether Bash(python3 scripts/*) is dropped is NOT documented → prefer exact per-script rules. Fallback: 3 consecutive or 20 total classifier blocks pause auto mode (not configurable); /permissions → Recently denied, r to retry.
- Auto mode first Read/Grep/Glob outside working dirs prompts; "Block from now on" writes permissions.blockReadsOutsideWorkingDirectories: true to USER settings, which disables autoMemoryDirectory from the project file (no auto memory loaded/saved) → answer "Keep allowing" or put autoMemoryDirectory in ~/.claude/settings.json.
- Bash rules: * matches anything incl. spaces; trailing " *" also matches bare command; :* suffix == " *"; compound commands split on && || ; | |& & newline and each subcommand must match independently — a rule containing | (Bash(curl * | bash*)) is undocumented, so don't use it; curl|bash is blocked by the built-in auto-mode soft_deny or by a PreToolUse hook. Bash(curl *) doesn't catch /usr/bin/curl or sh -c.
- Read/Edit rules: //abs, ~/home, /rel-to-settings-source (project → working dir; user → ~/.claude/), path or ./path rel to cwd; only Edit(path)/Read(path) are consulted (Write/Glob/NotebookEdit/MultiEdit path rules ignored with warning, except Glob in --allowedTools). Read deny also blocks Edit/Write on the same path. Deny does NOT reach Python/Node scripts that open files themselves; OS-level block only via sandbox.enabled: true (Read deny → sandbox.filesystem.denyRead).
- Read-only commands (ls cat echo pwd head tail grep find wc which diff stat du cd, read-only git) run without prompt in every mode except fenced paths; in Manual they still prompt for unquoted globs with find/sort/sed/git, docker -H/--context, file -m/-f, UNC paths, unparseable or >10,000-char commands, cd+git, cd+ambiguous redirect.
- statusLine: {"type":"command","command":"...","padding":N(default 0),"refreshInterval":N(min 1, re-runs in addition to events),"hideVimModeIndicator":bool}; stdin JSON has model.id/display_name, cwd, workspace.current_dir/project_dir, session_id, prompt_id (absent before first input), transcript_path, version, output_style.name, cost.total_cost_usd/total_duration_ms, context_window.total_input_tokens/total_output_tokens/context_window_size/used_percentage/remaining_percentage/current_usage (used_percentage and remaining_percentage may be null early; current_usage null before first call and after /compact), exceeds_200k_tokens, effort.level, rate_limits.five_hour/seven_day.used_percentage (Pro/Max only, after first response), vim.mode, agent.name.
- hooks: object keyed by event → [{matcher, hooks:[{type:"command",command:...}]}]; merge across files; managed hooks can't be removed; project hooks run with parent-folder trust and in -p; disableAllHooks false in project file beats true in user file (use --settings). ConfigChange matchers: user_settings, project_settings, local_settings, policy_settings, skills; input adds source and file_path; exit 2 or {"decision":"block"} blocks (not policy_settings), silently.
- Hook common input fields for the jsonl logger: session_id, prompt_id, transcript_path (async, may lag), cwd, scratchpad_dir (v2.1.257+), permission_mode (Manual arrives as "default"), effort.level, hook_event_name, agent_id/agent_type in subagents. CLAUDE_CODE_SESSION_ID matches session_id and changes on /clear.
- env block: string values only; overrides shell exports; project/local env applies after trust (or at startup in -p); CLAUDE_CONFIG_DIR, HOME, TMPDIR, XDG_* etc. ignored from project/local.
- autoMode (user file only): {environment, allow, soft_deny, hard_deny: [prose...], classifyAllShell: bool}; always include "$defaults" or the built-in list for that section is replaced; precedence hard_deny > soft_deny > allow > explicit user intent; claude auto-mode defaults prints built-ins; /auto-mode-setup writes environment entries to ~/.claude/settings.json.
- Other keys worth using in babel-os .claude/settings.json: language "portuguese" (verbatim instruction), timeZone "America/Sao_Paulo", timeFormat "24-hour" (any value with % is strftime), cleanupPeriodDays 3650 (0 fails validation), plansDirectory "./plans", autoMemoryDirectory (absolute or ~/), spinnerVerbs {mode append|replace, verbs[]} (replace with empty keeps built-ins), spinnerTipsOverride (project/local: plain string tips only; text ≤500 chars, ≤200 tips), outputStyle case-sensitive (Proactive, Concise, Explanatory, Learning; wrong case → Default silently), showThinkingSummaries, attribution {commit, pr, sessionUrl} (includeCoAuthoredBy deprecated).
- Auto memory native: autoMemoryEnabled default true; auto mode blocks writing to ~/.claude/projects/*.jsonl transcripts by default (reading is fine).
- macOS: babel-os lives in ~/Desktop, a system-protected folder; background sessions (--bg/agent view) may need separate folder access if reads fail with "Operation not permitted".
- Validation checklist: python3 json.load on the file; /status "Setting sources"; claude doctor; /permissions (incl. Auto mode tab); /hooks; accept trust dialog; ensure user settings lack blockReadsOutsideWorkingDirectories: true; statusline.py must tolerate null/missing fields.
